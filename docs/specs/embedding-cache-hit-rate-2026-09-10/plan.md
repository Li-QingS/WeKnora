# Embedding 缓存命中率优化 Plan

1. 固定并推送回退 tag，记录现有数据库命中和容量基线。
2. 抽取保守文本规范化函数，以规范文本生成现有格式的哈希键。
3. 为非规范文本增加旧键回查及规范键惰性提升。
4. 扩展 Batch 分组，保证同一规范文本只发一次，同时检查组内各旧键。
5. 使用进程级、批量感知的 flight registry 原子认领一组缓存键；相同冷请求共享结果，同时保留 Provider 批处理能力，并复制返回向量避免共享可变切片。
6. 扩展过程统计和模型用量页面。
7. 用 EnterpriseRAG corpus/queries 构造原文重复和编辑器格式漂移，运行前后算法对比；用慢速假 Provider 验证并发调用数。
8. 完成全仓回归、代码 review、结果报告、提交和推送。
9. 用 Context 携带 Embedding 调用用途，在缓存包装器中同时保留总量统计并累计分用途统计；文档索引入口标记为 `document_index`，Wiki 节点评测标记为 `wiki_evaluation`，未标记调用归入 `other`。
10. API 为每个模型返回分用途计数；前端只用 `document_index` 计算“文档向量化复用率”，并说明上传、重解析、重建索引属于统计范围，Wiki 评测与 RAG 查询不计入。

## 边界

- 本轮提高“精确内容因格式差异造成的漏命中”和“并发冷启动重复调用”。
- 内容真实变化、模型配置变化、跨租户请求仍必须未命中。
- SQL 容量治理沿用上一轮结论，作为独立后续工作，不与命中率改造混在一起。
- 分用途统计仍为进程内累计，不改变向量缓存键、持久缓存内容或模型调用行为。
