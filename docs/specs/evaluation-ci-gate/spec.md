# CI 质量回归门禁（课题三 WP3）Spec

> 状态：待审批（2026-09-01）
> 课题：腾讯犀牛鸟 · WeKnora 开源训练营 课题三「质量评测基线与成本可观测」
> 工作包：WP3 CI 质量回归门禁（WP1 持久化、WP2 可复现 Runner 已完成）

## 背景

WP2 已经提供“一条命令跑评测并生成报告”，报告里有 `config_hash`、数据集哈希、12 项指标和复现命令，数据库记录与文件可互相追溯。但目前还没有回答一个关键问题：**这次代码改动让质量变好了还是变差了？**

现在开发者改代码后，只要编译和普通测试通过就能合入，评测质量没有自动门禁。一次检索链路的小改动可能让召回率从 0.9 掉到 0.7，但没有任何机制发现。WP3 的目标是建立“质量体检器”：把可信运行的指标固化成基线，之后每次运行自动对比，退化就返回退出码 2 并让 CI 失败。

## 目标

- G1：用 YAML 文件保存一份“考试标准”：数据集、配置哈希、各指标基线与阈值。
- G2：提供比较器，把当前 `evaluation-result.json` 与基线对比，输出通过/失败和具体差异。
- G3：指标退化时返回 WP2 已预留的退出码 `2`，可被脚本和 CI 直接消费。
- G4：基线更新必须是显式、有记录的行为，不允许被悄悄覆盖。
- G5：提供一个可复现的“人为制造退化”演示，证明 CI 能拦住召回退化。
- G6：新增 GitHub Actions workflow，在相关路径的 PR 和手动触发时执行质量门禁。
- G7：不新增数据库迁移，不改变指标算法与评测链路。

## 功能需求

- **F1：基线文件。** 提供 YAML 基线文件，至少包含：
  - `config_hash` 与 `dataset.sha256`，用于确认“同一张考卷”；
  - 检索指标（Precision/Recall/NDCG@3/NDCG@10/MRR/MAP）与生成指标（BLEU1/2/4、ROUGE1/2/L）的阈值；
  - 每个指标支持三种规则：绝对下限 `min_value`、最大绝对下降 `max_absolute_drop`、最大相对下降 `max_relative_drop`；
  - 元数据：批准 commit、批准人、创建时间、备注。
  随仓库提供一个基于 demo 数据集的示例基线。

- **F2：比较器。** 提供 `weknora eval compare` 命令：
  - 输入当前 `evaluation-result.json` 与基线 YAML；
  - 先校验 `config_hash` 与 `dataset.sha256` 是否匹配基线，不匹配直接报配置/基线错误；
  - 逐指标计算当前值与基线值的差异，按阈值规则判定通过或失败；
  - 输出机器可读结果（JSON）或人可读摘要（text），包含每个指标的基线值、当前值、delta 和判定；
  - 全部通过退出码 0，任一退化退出码 2，基线/配置错误退出码 3。

- **F3：Runner 集成。** `weknora eval run` 支持 `--baseline <path>`：成功运行并生成报告后自动执行比较；退化时进程以退出码 2 结束，同时报告仍保留在磁盘上。

- **F4：基线生成与更新。** 提供从可信运行生成基线文件的命令或 Makefile 目标：
  - 输入一份已验证的 `evaluation-result.json`；
  - 写入基线 YAML，包含 `config_hash`、数据集哈希、当前指标值（作为 baseline）与调用方提供的阈值；
  - 必须提供批准信息（`--approved-by` 等）；
  - 覆盖已有基线必须显式传覆盖参数，普通命令不允许静默覆盖。

- **F5：退化演示。** 提供一套可复现的“故意退化”方法，例如一份相关性被破坏的演示数据集或配置：
  - 正常配置运行通过（退出码 0）；
  - 退化配置运行后至少 Recall 明显下降（退出码 2）；
  - 命令与预期输出写入文档，可被评审直接复现。

- **F6：GitHub Actions 质量门禁。** 新增 `rag-quality-gate` workflow：
  - 触发：涉及 `internal/**`、`config/**`、`dataset/**`、`migrations/**`、`evaluation/**`、CLI eval 相关路径的 PR，以及手动 `workflow_dispatch`；
  - 配置了真实评测服务 secrets 时，执行 `make eval-ci`（运行评测 + 对比基线），退化时任务失败并上传报告；
  - 未配置 secrets 时，执行比较器自测（用仓库内提交的样例结果与基线验证比较器逻辑），避免 PR 静默跳过。

- **F7：报告联动。** 执行带 `--baseline` 的运行或 `eval-ci` 时，`evaluation-report.md` 增加“与基线对比”小节，列出通过/退化的指标与 delta。

## 非功能需求

- **N1：确定性。** 相同的结果文件与基线文件，比较结果和退出码必须完全一致，不依赖运行环境。
- **N2：兼容 WP2 退出码。** 复用 0/2/3/4/5 约定；`2` 只表示指标退化，`3` 表示基线/配置/数据集错误。
- **N3：无敏感信息。** 基线文件、比较输出与报告中不得出现 API Key、endpoint 凭据、Prompt 正文。
- **N4：低侵入。** 不新增数据库表，不改变评测执行链路、指标算法与 WP2 报告格式；`evaluation-result.json` 字段保持兼容。
- **N5：可测试。** 比较器、基线生成、Runner 集成与 CLI 错误码均有单元测试；至少有一个端到端退化演示。
- **N6：跨部署可用。** 比较器只依赖结果文件和基线文件，不依赖服务端或数据库，可在任何机器/CI 上运行。

## 不做的事

- **不做成本台账。** 模型调用费用、token 统计与成本阈值属于 WP4；基线文件中不实现 `estimated_cost_usd` 规则。
- **不做 Embedding 缓存与 Prompt 缓存实验。** 属于 WP5 / WP6。
- **不做前端页面与演示材料。** 属于 WP7。
- **不做样本级守护。** 报告当前只有聚合指标，没有逐样本检索/生成明细；关键样本级规则留待报告扩展后实现。
- **不做完整 mock 模型服务。** 公共 CI 的真实评测通过仓库 secrets 提供；确定性 mock 模型服务可作为后续增强，不阻塞本期门禁闭环。
- **不做 JUnit XML。** 本期以退出码和 GitHub Actions 任务失败表达门禁结果，JUnit 输出留作可选增强。
- **不自动接受新基线。** 任何基线更新都需要显式命令、批准信息与代码评审。

## 验收标准

- **AC1（对应 F1）：基线文件存在且可解释。** 仓库包含 demo 基线 YAML，`config_hash` 与真实 demo 运行一致，包含检索与生成指标阈值和批准元数据。

- **AC2（对应 F2）：通过场景退出码 0。** 用与基线同配置的 `evaluation-result.json` 执行比较器，输出各指标判定，进程退出码 0。

- **AC3（对应 F2/F5）：退化场景退出码 2。** 用故意降低 Recall 的结果执行比较器（或运行退化演示），输出包含基线值、当前值、delta 与失败指标，退出码 2。

- **AC4（对应 F2）：考卷不匹配退出码 3。** `config_hash` 或 `dataset.sha256` 与基线不一致时，比较器拒绝比较并返回退出码 3，不输出“通过”。

- **AC5（对应 F3）：Runner 集成。** `weknora eval run --baseline <path>` 在退化时以退出码 2 结束，且报告文件仍生成。

- **AC6（对应 F4）：基线显式更新。** 生成基线需要批准信息；覆盖已有基线需要显式参数；不带参数时提示并返回配置错误（退出码 3）。

- **AC7（对应 F6）：workflow 存在且可执行。** `.github/workflows/rag-quality-gate.yml` 已提交；无 secrets 时自测步骤通过，有 secrets 时执行真实评测与比较。

- **AC8（对应 F5）：退化演示可复现。** 文档记录正常与退化两条命令；本地真实执行证明正常退出码 0、退化退出码 2。

- **AC9（对应 N3）：无敏感信息泄漏。** 基线文件、比较输出和报告中不出现 API Key、endpoint 凭据、Prompt 正文。

- **AC10（对应 N5）：自动化验证。** 比较器与基线生成单测通过；`go build ./...`、服务端/客户端/CLI 测试与 vet 全部通过。

- **AC11（对应 N4）：无迁移、指标算法不变。** 本次改动不新增数据库迁移，不修改 12 项指标实现；`evaluation-result.json` 结构保持兼容。

## 已确认的取舍（需求澄清记录）

1. 基线以 `config_hash + dataset.sha256` 作为“考卷”标识，不匹配即拒绝比较。
2. 阈值规则首版支持绝对下限、最大绝对下降、最大相对下降；成本/耗时上限不属于 WP3。
3. 公共 CI 真实评测使用仓库 secrets 提供的服务；无 secrets 时跑比较器自测，避免 PR 静默跳过。
4. 完整 mock 模型服务、样本级守护、JUnit XML 明确不纳入本期，作为后续增强。
