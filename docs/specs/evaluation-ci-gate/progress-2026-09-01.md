## 实现内容

### 基线文件

- `evaluation/baselines/demo.yaml`：记录 demo 的 `config_hash`、`dataset.sha256`、12 项指标基线与阈值规则，以及批准元数据。
- 阈值规则支持 `min_value`、`max_absolute_drop`、`max_relative_drop`。

### 比较器

- `weknora eval compare --result <json> --baseline <yaml>`：
  - 校验 `config_hash` 与 `dataset.sha256`，不匹配拒绝比较；
  - 逐指标输出 baseline / current / delta / pass；
  - 全过退出 0，退化退出 2，基线/配置错误退出 3。
- 比较器只依赖结果文件与基线文件，可在任意机器/CI 复现同一判定。

### Runner 集成

- `weknora eval run --baseline <yaml>` 成功运行后自动比较。
- `evaluation-result.json` 增加可选 `comparison` 字段；`evaluation-report.md` 增加“Baseline comparison”小节。
- 普通不带 baseline 的运行输出结构不变。

### 基线生成

- `weknora eval baseline create --result ... --output ... --approved-by ... --approved-commit ... [--force]`。
- 必须有批准信息；覆盖已有文件需要 `--force`；支持 `--dry-run`。

### 入口与 CI

- `make eval-ci CONFIG=... BASELINE=...`：跑评测 + 对比基线。
- `make eval-baseline-generate`：从最近一次可信运行生成基线。
- `.github/workflows/rag-quality-gate.yml`：
  - 有 `WEKNORA_EVAL_HOST` / `WEKNORA_EVAL_TOKEN` secrets 时执行真实评测门禁；
  - 无 secrets 时执行比较器自测（pass 期望 0，degraded 期望 2）；
  - 总是上传 `artifacts/evaluation/**`。

### 夹具

- `evaluation/fixtures/evaluation-result-pass.json`：与基线同 `config_hash` 的正常结果。
- `evaluation/fixtures/evaluation-result-degraded.json`：同 `config_hash`、同数据集哈希，但 Recall 等检索指标明显下降。

## 端到端验证

### 1. 比较器自测

```bash
./cli/bin/weknora eval compare \
  --result evaluation/fixtures/evaluation-result-pass.json \
  --baseline evaluation/baselines/demo.yaml
echo $?   # 0

./cli/bin/weknora eval compare \
  --result evaluation/fixtures/evaluation-result-degraded.json \
  --baseline evaluation/baselines/demo.yaml
echo $?   # 2
```

degraded 夹具输出 6 个失败指标（precision/recall/ndcg3/ndcg10/mrr/map），退出码 2。

### 2. 真实质量门禁

```bash
WEKNORA_HOST=http://localhost:8080 WEKNORA_TOKEN=<token> \
make eval-ci CONFIG=./evaluation/configs/default.yaml \
  BASELINE=./evaluation/baselines/demo.yaml
echo $?   # 0
```

结果：

- 退出码 0；
- `artifacts/evaluation/evaluation-report.md` 包含“Baseline comparison”，全部 PASS；
- `evaluation-result.json` 的 `comparison.pass=true`、`failed_count=0`；
- 数据库 run 的 `config_hash` 与基线一致。

### 3. 退化路径证据

- 通过夹具证明同一 `config_hash` 下 Recall 下降会返回退出码 2；
- 尝试用严格阈值跑真实退化门禁时，服务端最后一个样本的模型调用长时间挂起，未完成；退出码 2 的证据以夹具 + 单测为准。
