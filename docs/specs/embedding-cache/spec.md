# Embedding 缓存（课题三 WP5）Spec

> 状态：待审批（2026-09-02）
> 课题：腾讯犀牛鸟 · WeKnora 开源训练营 课题三「质量评测基线与成本可观测」
> 工作包：WP5 Embedding 缓存（WP1-WP4 已完成）

## 背景

文档入库和检索都会反复调用 Embedding 模型。同一段文本如果被重复向量化，既增加延迟也增加费用。WP4 已经把每次模型调用记进台账，现在需要一个缓存层，让相同输入直接复用向量，并用 WP4 的调用次数/费用做前后对比。

当前 Embedding 调用链是：业务 → cost wrapper → langfuse/debug → concurrency → provider。缓存应该放在 provider 之前、concurrency 之内或更早，让命中时不再发起真实模型调用。

## 目标

- G1：相同租户、相同模型、相同维度、相同文本的 Embedding 请求直接复用缓存向量。
- G2：批量请求支持部分命中：只调用模型补算未命中的文本，并保持返回顺序。
- G3：缓存默认关闭、可配置开启；缓存不可用时 fail-open，不影响正常调用。
- G4：提供命中/未命中的可观测统计，可与 WP4 台账结合展示调用次数下降。
- G5：不降低向量正确性：模型维度或签名变化后旧缓存不可复用。

## 功能需求

- **F1：缓存键。** 缓存键至少包含租户 ID、模型 ID、模型维度、文本 SHA-256；不允许不同租户/模型/维度共用缓存。

- **F2：缓存读写。** 新增 `embedding_cache_entries` 表，支持：
  - 按键查询向量；
  - 写入向量；
  - 命中计数自增；
  - 唯一约束 `(tenant_id, model_id, dimension, text_hash)`。

- **F3：缓存包装层。** 在 Embedding 客户端增加 cache wrapper：
  - `Embed(text)`：命中直接返回，未命中调用模型并写缓存；
  - `BatchEmbed(texts)`：逐条查缓存，未命中部分合并调用模型，按原顺序合并结果；
  - 缓存未安装时不改变现有行为。

- **F4：开关与降级。** 通过环境变量控制是否启用缓存（默认关闭）；缓存读写失败只记日志并直接调用模型，不阻断业务。

- **F5：可观测统计。** 提供进程级命中/未命中计数，并通过 API 暴露，便于页面或脚本读取；WP4 台账中 Embedding 调用次数作为“缓存前/后”对比依据。

- **F6：双库迁移。** PostgreSQL 与 SQLite 各新增缓存表迁移，SQLite 守卫测试同步更新。

## 非功能需求

- **N1：正确性。** 相同文本返回的向量必须与不开启缓存时一致；不同模型/维度/租户互不串用。
- **N2：隔离。** 缓存写入和查询必须带租户边界。
- **N3：低侵入。** 不修改指标、评测链路与 WP4 台账结构；缓存只发生在 Embedding 客户端层。
- **N4：可测试。** 缓存仓库、包装层、批量部分命中、开关、统计均有单测；至少一个端到端“缓存前后调用次数对比”。
- **N5：容量与清理。** 本期只记录最近写入时间，不做自动清理；保留策略留待后续。

## 不做的事

- **不做 Redis 缓存。** 本期使用数据库表，Lite 与标准模式行为一致。
- **不做 LRU/容量限制。** 只做按模型维度的精确键匹配。
- **不做缓存预热与主动失效。** 模型配置变化后通过键中的维度/模型 ID 自然失效。
- **不做 Prompt 缓存。** 属于 WP6。
- **不做复杂统计页面。** 只暴露命中/未命中统计 API，前端可后续接入。

## 验收标准

- **AC1（对应 F6/N3）：双库迁移。** PG 与 SQLite 创建 `embedding_cache_entries`，守卫测试更新到新版本；从零建库与升级路径通过。

- **AC2（对应 F1/N1）：键正确。** 相同文本、相同模型/维度/租户命中；租户、模型或维度任一不同则不命中。

- **AC3（对应 F3）：单条命中。** 第二次 Embedding 同一文本不再调用底层模型，返回与首次相同的向量。

- **AC4（对应 F3）：批量部分命中。** 混合已缓存/未缓存文本时，只对未缓存文本发起一次模型调用，返回顺序与输入一致。

- **AC5（对应 F4）：开关与降级。** 默认关闭时行为不变；开启后缓存读写失败仍能正常返回模型结果。

- **AC6（对应 F5）：统计可见。** 命中/未命中计数可读，WP4 台账中 Embedding 调用次数在开启缓存后下降。

- **AC7（对应 N2/N1）：隔离与正确性。** 不同租户/模型/维度互不串用；开启缓存前后向量一致。

- **AC8（对应 N4）：自动化验证。** 相关单测与端到端对比通过；`go build` / `go test` / vet 通过。

## 已确认的取舍（需求澄清记录）

1. 缓存后端用数据库表，不用 Redis，保证 Lite/标准模式一致且可持久。
2. 默认关闭，由环境变量开启；缓存失败 fail-open。
3. 命中统计先用进程级计数 + API，不做历史趋势表。
4. 不做容量清理与预热，模型配置变化通过键自然失效。
