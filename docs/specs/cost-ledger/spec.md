# 模型调用台账与费用估算（课题三 WP4）Spec

> 状态：待审批（2026-09-02）
> 课题：腾讯犀牛鸟 · WeKnora 开源训练营 课题三「质量评测基线与成本可观测」
> 工作包：WP4 模型调用台账与费用估算（WP1-WP3 已完成）

## 背景

WP1-WP3 解决了“评测能跑、能复现、能进 CI”的问题，但课题三还要求：**模型调用次数、缓存命中率与费用可以按模型查询，数据来自数据库而不是日志**。

当前现状：

- Chat 调用已有 `TokenUsage`，部分写进 `messages.usage`，但没有覆盖 Embedding / Rerank / VLM / ASR；
- 模型调用主要靠日志和可选的 Langfuse，无法在数据库里按租户、模型、时间统计；
- 没有价格配置和价格快照，无法计算历史费用；
- 没有模型调用汇总/明细 API 和页面。

WP4 的目标是在统一模型客户端层加“记账装饰器”，所有模型调用自动写结构化台账，并提供价格配置、汇总/明细查询和一个最小展示页面。

## 目标

- G1：每次模型调用（Chat / Embedding / Rerank / VLM / ASR）都落一条结构化记录，包含租户、模型、类型、用途、状态、耗时、Token 用量、费用估算。
- G2：价格可配置，调用时保存价格快照，历史费用不随价格调整而改变。
- G3：未知价格的调用仍然记录，费用显示 `unknown`，不错误地记成 0。
- G4：提供按租户、模型、时间筛选的汇总和明细 API。
- G5：提供最小前端页面展示调用次数、Token 与估算费用。
- G6：不保存 Prompt 正文和 API Key，租户隔离在所有查询路径生效。

## 功能需求

- **F1：模型调用记录。** 新增 `model_call_records` 表，至少包含：
  - 租户 ID、模型 ID、模型名称、模型类型（Chat/Embedding/Rerank/VLM/ASR）；
  - 调用用途（来自现有 `LLMCallMetadata` 的 purpose）；
  - 状态（成功/失败）、错误类型、错误摘要、耗时；
  - Token 用量：prompt / completion / total / cache_read / cache_write / cache_miss；
  - 非 Token 计费模型：unit_type 与 unit_count（如字符数、文档数、请求数）；
  - 价格快照、估算费用（可为空）；
  - 会话、用户、trace_id、request_group_id、创建时间。

- **F2：统一记账。** 在 Chat、Embedding、Rerank、VLM、ASR 的模型客户端包装层增加记账装饰器，调用完成后写入台账：
  - 非流式 Chat 调用结束即记录；
  - 流式 Chat 在流结束时使用最终 Usage 记录；
  - Embedding 在供应商不返回 Token 时沿用现有近似估算；
  - Rerank 按 query + documents 估算输入量；
  - 失败调用也要记录状态与错误摘要。

- **F3：价格配置。** 新增 `model_prices` 表，支持按租户 + 模型配置：
  - input / output / cache_read / cache_write 每百万 Token 价格；
  - 非 Token 模型可配置 unit_type + unit_price；
  - 币种（默认 USD）；
  - 写入记录时保存价格快照 JSON，之后改价不影响历史记录。

- **F4：费用估算。** 调用结束时按价格快照计算估算费用：
  - `input_tokens / 1e6 * input_price` + `output_tokens / 1e6 * output_price` + cache 项；
  - 非 Token 模型按 `unit_count * unit_price`；
  - 任意价格缺失时费用为 `null`，不显示 0。

- **F5：明细 API。** `GET /api/v1/model-calls`：
  - 支持分页（page/page_size）与筛选：模型 ID、模型类型、状态、开始时间区间；
  - 只返回当前租户数据；
  - 每条包含 Token、耗时、费用、trace_id。

- **F6：汇总 API。** `GET /api/v1/model-calls/summary`：
  - 按模型或类型返回调用次数、成功数、失败数、Token 汇总、cache 读写 Token、估算费用；
  - 同样支持时间区间筛选与租户隔离。

- **F7：价格 API。** 提供价格的读取与写入接口，用于模型管理页面配置价格；价格变更只影响之后的新调用。

- **F8：最小页面。** 在模型管理区域新增“模型用量”入口：
  - 汇总表：按模型显示调用次数、Token、费用；
  - 明细表：最近调用记录，可分页；
  - 时间/模型筛选为加分项，不做复杂图表。

- **F9：双库迁移。** PostgreSQL 与 SQLite 各新增一张/多张迁移，SQLite 守卫测试同步更新。

## 非功能需求

- **N1：租户隔离。** 写入和查询都必须带租户边界；跨租户读取返回不存在或无数据。
- **N2：敏感信息最小化。** 不保存 Prompt 正文、API Key、endpoint 凭据；错误摘要只保留类型与可定位原因。
- **N3：性能。** 记账发生在调用结束之后，不占用模型请求路径；若同步写库带来可测延迟，优先保证正确性并记录基准，后续再做异步/批量。
- **N4：双库兼容。** 新表在 PG 与 SQLite 上行为一致，JSON 字段遵循现有惯例。
- **N5：可测试。** 记账装饰器、价格计算、repository、API 均有单测；至少一个真实调用端到端落库。
- **N6：不破坏现有调用。** 记账装饰器失败只记日志，不影响模型调用成功或失败返回；默认开关为开启，但可用配置禁用。

## 不做的事

- **不做供应商账单对账。** 阶梯价、免费额度、批处理价、币种换算、税费等由真实账单处理，不在本期实现。
- **不做 Langfuse 替代。** 台账与 Langfuse 可同时开启，互不影响。
- **不做复杂图表页面。** 本期只有汇总表 + 明细表。
- **不做成本阈值门禁。** 把费用接入 WP3 门禁属于后续增强。
- **不做数据保留策略。** 明细清理/日聚合留待后续。
- **不存 Prompt 正文。** 即使已有 Langfuse 调试能力，台账也不复制正文。

## 验收标准

- **AC1（对应 F9/N4）：双库迁移。** PG 与 SQLite 迁移创建新表，SQLite 守卫测试更新；从零建库与升级路径通过。

- **AC2（对应 F2）：Chat 落库。** 一次真实/测试 Chat 调用后，`model_call_records` 出现记录，包含正确租户、模型、状态、Token、耗时与价格快照。

- **AC3（对应 F2）：Embedding 落库。** 一次 Embedding 调用后出现记录，Token 为近似值或供应商值。

- **AC4（对应 F2/N2）：失败落库。** 人为制造模型调用失败，记录状态为 failed、错误类型与摘要可见，不存 Prompt/Key。

- **AC5（对应 F4）：未知价格为空。** 未配置价格的模型调用费用为 `null`，页面/API 显示 unknown，不显示 0。

- **AC6（对应 F5）：明细查询。** `GET /api/v1/model-calls` 支持分页与筛选，只返回当前租户数据。

- **AC7（对应 F6）：汇总查询。** `GET /api/v1/model-calls/summary` 返回按模型/类型的调用次数、Token、费用。

- **AC8（对应 F3/F7）：价格配置。** 设置某模型价格后，新调用使用新价格并保存快照；改价后旧记录费用不变。

- **AC9（对应 F8）：页面可见。** 模型用量页面可打开并展示汇总与明细数据。

- **AC10（对应 N1/N2）：隔离与脱敏。** B 租户看不到 A 租户的调用记录；数据库与 API 响应中无 Prompt 正文、API Key、endpoint 凭据。

- **AC11（对应 N5/N6）：回归。** 记账装饰器失败不影响模型调用；`go build` / `go test` / vet 通过。

## 已确认的取舍（需求澄清记录）

1. 记账采用“模型客户端包装层 + 全局 Recorder hook”的方式，镜像现有 Langfuse manager，避免在业务代码里手写埋点。
2. 价格快照随调用记录保存，价格表只影响后续新调用。
3. 本期先保证正确落库和查询，不做异步批量；若基准显示明显开销再优化。
4. 页面只做最小汇总 + 明细表，图表与筛选器是加分项。
