## 观察

1. 重复收益最明显的两个场景确实是：
   - `wiki_page_modify`
   - `wiki_chunk_citation`
2. 同一文档连续重建后，`wiki_candidate_slug` 与 `wiki_summary` 已经能命中 83%-90%，
   说明 qwen 的供应商前缀缓存对同一份文档是有效的。
3. 但 `wiki_page_modify` 命中率波动在 8%-14%，`wiki_chunk_citation` 稳定在约 10.4%，
   仍有明显优化空间。
4. 页面修改与 chunk 引用是否命中，依赖共享前缀是否在厂商缓存 TTL 内保持字节一致。
5. 后续修改 Prompt 后，应至少跑 2 次并取稳定值，不能只看一次运行。

## 后续对比目标

改造后同一实验下，希望看到：

- `wiki_page_modify` 命中率明显高于当前波动区间上沿 14%；
- `wiki_chunk_citation` 命中率明显高于 10.5%；
- 或 `cache_miss` 与总费用明显下降。

如果命中率没有提升，需要先确认 qwen 接口是否稳定支持前缀缓存，再决定是否继续优化 Prompt。
