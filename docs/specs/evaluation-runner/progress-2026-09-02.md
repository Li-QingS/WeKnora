## 分块参数链路

- `evaluation/configs/enterprise.yaml` 增加 `chunking`（strategy / chunk_size /
  chunk_overlap / token_limit / languages）；
- CLI YAML → SDK → `POST /api/v1/evaluation` 全链路透传；
- 服务端校验并归一化参数，把实际生效配置写入 `config_snapshot.chunking`，
  同时参与 `config_hash`；
- 评测开始前按该配置调用现有 Go chunker 把每篇语料切块再灌入临时知识库，
  chunk 仍是原 passage 的连续子串，因此现有“按内容回映射 passage id”的指标
  逻辑保持有效；
- 不传 `chunking` 时保持历史 passage-per-chunk 行为，旧配置与旧哈希不受影响；
- Runner 报告的 JSON 与 Markdown 会展示本次运行实际使用的 chunking 参数。

## 评测中心前端可直接发起评测

- 设置页“评测中心”新增“新建评测”面板；
- 数据集下拉来自新增的 `GET /api/v1/evaluation/datasets`，展示 `default` /
  `demo` / `enterprise_rag` 及其样本数；
- 可分别选择 Embedding / KnowledgeQA / Rerank 模型，留空则使用服务端默认；
- 可配置 chunking strategy、chunk_size、chunk_overlap；
- 点击“开始评测”调用 `POST /api/v1/evaluation`，前端每 2 秒轮询进度，
  终态后刷新历史并打开本次运行详情；
- 历史详情中展示 `config_snapshot.chunking`，运行记录仍来自数据库。

## 单次运行同时给出四类结果

- 检索准确性：`retrieval_metrics`；
- 答案质量：`generation_metrics`；
- 成本：每次评测把所有模型调用写入 `request_group_id = <run_id>` 的台账，
  成功后按 run 汇总 `cost_metrics`（调用次数、Token、估算费用）；
- 耗时：评测结束写入 `latency_metrics`（总耗时、每样本平均耗时、模型调用耗时）。

以上字段写入 `evaluation_runs.metric`，Runner 报告与评测中心详情都会展示。

## 评测中心历史删除

- 新增 `DELETE /api/v1/evaluation/runs/:id`，仅 Admin+ 可用；
- 只允许删除 pending/running 之外的终态记录，避免后台任务继续写已删行；
- 删除按租户隔离，其他租户返回 not found；
- 模型用量台账 `model_call_records` 不随评测历史删除，费用审计记录保留；
- 前端历史表增加“删除”操作，二次确认后刷新列表。
