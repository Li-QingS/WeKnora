# 模型用量与评测中心体验完善 Spec

> 状态：已自审通过（2026-09-10）

## 背景与目标

模型用量页把日期转换为 UTC 时间戳后再查询无时区的数据库字段，导致用户选择同一天时可能漏掉当天晚间调用。Wiki 的实体、概念覆盖和连接结构评分已经由后端实现，前端也有基础页面，但入口和结果层级不够清晰。

本次完成两项改进：日期选择按日历日查询完整自然日；评测中心以统一的评测类型入口组织 RAG 与 Wiki，并在 Wiki 页面明确区分“节点覆盖”和“连接结构”。

在功能正确的基础上，本轮继续改善日常使用体验：用户应先看到本次评测或查询的结论，再按需查看配置、运行记录和原始明细；技术字段需要翻译为可理解的中文，长标识和大表格不能妨碍浏览。

## 功能要求

- 选择相同开始日和结束日时，查询该日 `00:00:00`（含）至次日 `00:00:00`（不含）的全部模型调用。
- 日期接口接受 `YYYY-MM-DD`；带时区的 RFC3339 参数继续按原有精确时间语义处理。
- 评测中心显著展示 RAG 问答评测与 Wiki 图谱评测两个入口及各自测量内容。
- Wiki 配置区说明实体、概念覆盖率和有向连接 Precision/Recall/F1，生成模型与评分模型用途清楚。
- Wiki 结果按节点覆盖、连接结构、运行开销分组，并保留节点和边明细下钻。
- 不修改既有 Wiki 评分公式、后端运行流程或 RAG 指标。
- 模型用量页先展示调用次数、Token、失败次数和估算费用，再展示各模型及调用明细；价格配置默认收起。
- 模型类型、调用目的、运行状态、匹配方式和节点类型使用中文展示，原始值仍通过悬停等方式保留。
- RAG 与 Wiki 运行记录使用短 ID 并提供明确的“查看”操作；结果指标需要给出中文名称和用途说明。
- 表格标题、滚动区域、数字对齐和窄屏布局应便于扫描，不改变接口或持久化结构。

## 验收标准

- 2026-09-08 至 2026-09-08 生成日期参数 `from=2026-09-08&to=2026-09-08`，后端转换为 `[2026-09-08T00:00:00Z, 2026-09-09T00:00:00Z)`。
- 恰好位于次日零点的记录不计入前一天；当天最后时刻的记录计入。
- 评测中心入口、Wiki 配置和结果页均能直接看出节点覆盖与有向连接两类评测。
- 前端测试、类型检查和生产构建通过；相关 Go 单元测试通过。
- 模型用量首屏能直接回答“调用了多少、消耗多少、是否失败、花费多少”；价格设置不再挤占主要分析区域。
- RAG/Wiki 评测结果无需理解内部字段名即可识别指标含义，运行记录有清晰查看入口。
- 桌面端表格与窄屏页面均不存在标题跟随横向滚动、内容严重拥挤等问题。
